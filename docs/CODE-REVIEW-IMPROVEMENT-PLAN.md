# Tessellation Studio 코드 리뷰 및 개선 계획

- **검토일:** 2026-09-30
- **검토 범위:** React/TypeScript 앱, SVG 패턴 편집, 모바일/데스크톱 UI, Next.js 정적 export, Electron, Capacitor, 스크립트, 프로젝트 문서
- **검토 방식:** 현재 소스와 설정을 읽어 동작상 위험을 식별했습니다. 이 문서는 계획이며, 아래 개선 작업을 아직 구현하거나 런타임 검증한 것은 아닙니다.
- **우선순위:** P1 = 긴급, P2 = 사용자 영향이 큰 문제, P3 = 후속 품질 개선

## 요약

현재 구조는 도형별 렌더러와 편집기·미리보기·도구 모음을 분리했고, Electron 창은 격리·샌드박스 설정을 사용합니다. 다음 개선은 새 기능보다 **미리보기/저장 프레이밍의 정확성**, **편집·데모 상태의 일관성**, **키보드 및 모바일 접근성**, **핵심 동작의 자동 회귀 테스트**에 우선순위를 둡니다.

현재 확인된 P1 문제는 없습니다. P2는 사용자가 결과를 잘못 저장하거나 편집을 잃을 가능성이 있는 문제와 기본 접근성 문제를 포함합니다.

## 실행 계획

### 1단계 — 결과 프레이밍과 상호작용 신뢰성 (P2)

대상: R-01, R-02, R-03, R-06

1. 패턴 SVG 컨테이너의 실제 크기와 위치를 `ResizeObserver` 또는 요소 측정으로 읽고, 그 값을 패턴 offset 및 `viewBounds` 계산의 단일 기준으로 사용합니다.
2. PNG/SVG 저장이 현재 미리보기와 동일한 viewBox/경계를 사용하도록 내보내기 경로를 정리합니다. 저장 해상도는 별도로 설정하되 화면 중심·잘림 기준은 공유합니다.
3. 드래그 입력을 pointer events와 pointer capture 기반으로 정리해 SVG 경계 밖 이동 및 해제를 지원하고 마지막 좌표를 반영합니다.
4. 일반 데모와 사각형 데모의 상태 전이를 한 곳에서 관리합니다. 데모 중 도형을 바꾸면 데모를 명시적으로 종료하거나 도형 선택을 잠그고, 데모 재실행이 중복되지 않게 합니다.
5. 곡선 모드에서 여러 제어점을 지원하는 경로 생성 규칙을 정합니다. 모든 점을 부드러운 다중 Bézier segment로 사용하거나, 해당 모드에서는 점 추가를 제한하고 UI에 제약을 표시합니다.

**완료 기준**

- 사이드바가 있는 데스크톱과 상단 헤더가 있는 모바일에서 미리보기 패턴 중심이 사용 가능한 패턴 영역의 중심과 일치합니다.
- 동일 상태에서 화면 미리보기, PNG, SVG의 패턴 위치와 잘림이 일치합니다.
- 조절점을 SVG 밖으로 드래그했다가 놓아도 최종 위치가 반영되고 편집이 고착되지 않습니다.
- 모든 도형 및 데모 조합에서 동시에 두 데모가 나타나지 않고, 데모 종료 후 사용자가 편집기로 복귀할 수 있습니다.
- 곡선 모드의 각 표시 조절점은 결과 경로에 실제 영향을 줍니다.

### 2단계 — 키보드 및 보조 기술 접근성 (P2/P3)

대상: R-04, R-05, R-09

1. 조절점에 포커스 가능 속성, 도형/변/점 위치를 설명하는 접근 가능한 이름, 눈에 보이는 포커스 링을 추가합니다.
2. 화살표 키로 포인트를 일정 간격 이동하고 Shift+화살표 등으로 큰 간격 이동을 제공하되, 마우스 편집과 같은 대응 변 규칙을 사용합니다.
3. 도형 선택을 라디오 그룹 또는 상호 배타적 선택 상태로 노출하고, 격자 토글은 `aria-pressed`로 현재 상태를 전달합니다.
4. 모바일 메뉴가 닫혀 있을 때 자식 컨트롤을 탭 순서와 접근성 트리에서 제외합니다. 열 때 메뉴로 포커스를 이동하고, 닫을 때 메뉴 버튼으로 돌려보내며, Escape 동작 및 배경 상호작용을 검증합니다.

**완료 기준**

- 키보드만 사용해 도형을 선택하고 조절점을 이동하며 메뉴를 열고 닫을 수 있습니다.
- 스크린 리더에서 선택 상태와 토글 상태가 식별됩니다.
- 닫힌 모바일 메뉴의 링크/버튼은 포커스되지 않습니다.

### 3단계 — 회귀 테스트 및 실행 환경 명확화 (P2/P3)

대상: R-07, R-10

1. `engines.node`, README, CI/개발 가이드의 Node 요구사항을 하나로 맞추고 Next가 실제 요구하는 최소 patch 버전을 기준으로 삼습니다.
2. 정적 export를 유지할지 Next 서버 배포로 바꿀지 결정합니다. 정적 export를 유지하면 `next start` 대신 지원되는 static server/preview 절차를 문서화하고, 바꾸면 Electron/Capacitor 패키징 경로도 함께 검토합니다.
3. 테스트 도구를 선택해 단위/컴포넌트 테스트와 브라우저 통합 테스트 명령을 추가합니다.
4. 우선 다음 시나리오를 자동화합니다.
   - 도형/변형 변경과 편집 경로 초기화
   - 포인터 드래그, 경계 밖 release, 다중 제어점 곡선
   - 사각형/육각형 데모 시작·다음·이전·종료와 shape 변경
   - SVG/PNG 생성, 파일명, 실패 시 object URL 정리
   - 정적 export의 핵심 SVG 정의 및 반복 `<use>` 렌더

**완료 기준**

- README의 Node 버전과 package engine이 일치합니다.
- 정적/서버 배포 결정과 실제 동작 검증이 README에 반영됩니다.
- 핵심 회귀 시나리오가 로컬에서 재현 가능하며 CI 또는 명시된 검증 절차에서 실행됩니다.

### 4단계 — 유지보수 비용 절감 (P3)

대상: R-08, R-11, R-12, R-13

1. 사각형 데모가 시작 전 편집기 표시 상태를 보존하고 종료 시 복원하도록 상태 전이를 정리합니다.
2. 중복 favicon 스크립트 중 하나를 제거하거나 프로젝트 모듈 형식에 맞춰 통일합니다.
3. `App.tsx`에서 export 동작과 데모/에디터 상태 조정 책임을 전용 hook 또는 모듈로 분리하되, 안정성 개선과 테스트 추가 없이 구조만 바꾸지 않습니다.
4. Markdown 매뉴얼과 PPT 사이에 공통 콘텐츠 데이터를 사용하거나, 적어도 내용 변경 시 재생성/검증을 요구하는 절차를 둡니다.
5. 활성화된 PostCSS 설정을 확인하고 하나만 유지합니다. 실제로 사용되지 않는 Tailwind PostCSS 패키지는 제거 전에 빌드 결과를 비교합니다.

**완료 기준**

- 데모 종료 후 이전 편집기 표시 상태가 보존됩니다.
- 스크립트와 PostCSS 설정의 모듈 형식/실행 경로가 명확합니다.
- 역할 분리 후 기존 자동화 테스트와 앱 빌드가 동일하게 통과합니다.
- 매뉴얼 업데이트 절차가 문서화되어 Markdown/PPT 간 오래된 내용이 방치되지 않습니다.

## 위험과 구현 원칙

- **화면 측정 변경:** resize 중 잦은 상태 갱신과 hydration 차이를 피하고, 측정이 준비되기 전의 안전한 초기 렌더를 정의합니다.
- **포인터 전환:** 기존 터치 이벤트와 중복 입력이 발생하지 않도록 마우스/터치/펜을 pointer events로 한 번에 통합하고 실제 기기에서 검증합니다.
- **곡선 알고리즘:** 다중 점 곡선은 타일의 경계 연속성과 짝 변 변환 규칙을 함께 보장해야 하므로 단위 테스트를 먼저 둡니다.
- **정적 배포 결정:** Electron과 Capacitor가 `out/`에 의존하므로 `output: 'export'` 변경은 별도 영향 분석 없이 진행하지 않습니다.
- **범위 제한:** square free-form 편집은 별도 사용자 결정 전까지 이 계획에 포함하지 않습니다.
